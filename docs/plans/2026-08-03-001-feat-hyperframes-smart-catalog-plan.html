Hyperframes product plan · 2026-08-03 · proposed, not implemented

One catalog.
Two ways to find it.

Every Hyperframes user should be able to browse and search components locally. Signed-in users may explicitly ask HeyGen for smarter ranking, free of credits. Both paths must return the same installable catalog IDs, and neither path touches Hyperion.

Ship first
Local search

Private, deterministic, no sign-in, no Pinecone, and usable when HeyGen is unavailable.

Gated beta
Smart search

Authenticated HeyGen API, server-side semantic/hybrid retrieval, zero credits, bounded by rate limits.

Hard boundary
Hyperframes only

CLI, SDK, Studio and media-use. Hyperion and website-to-video remain unchanged.

01 · what / why / how

The decision we can make now

What

Add a versioned search artifact to the Hyperframes release, a pure local search engine, and two authenticated HeyGen catalog endpoints: browse metadata and smart search.

Why

The catalog is already larger than a human can scan comfortably. Local search protects openness and resilience; HeyGen search can improve paraphrase and multilingual recall without shipping provider secrets.

How

One canonical ID contract feeds CLI, Studio, SDK, API and media-use. The API searches only an immutable catalog digest the client says it can install.

Not a production claim: the old experiment studied which moves to place in an LLM prompt. It did not test human browsing, a top-10 API, Pinecone, the Studio UI, latency, demand, or abuse. Those are new gates, not inherited confidence.
02 · where “424” comes from

The catalog is generated, not hand-counted

The evaluated branch scans committed primitive source artifacts and the registry manifests at Git HEAD. It validates each source, merges reviewed duplicate names, sorts the result, and emits a shelf plus a machine-readable index.

25 primitives+109 blocks+302 components−12 reviewed overlaps=424 unique entries
Important: 424 is a snapshot from feat-video-primitives, not a permanent product limit. Main currently has a different registry count, and primitives must not appear in a public search result until they have an installable contract.

Source PR

→

Deterministic builder

Validate IDs, files, compatibility, duplicates and search fields.

→

Immutable release artifact

catalog-search.json + SHA-256 digest, bundled with the CLI and indexed remotely.

When a component is added

Its manifest must pass schema and install tests. The builder adds it to a new digest. CI builds a new remote namespace and queries it before that digest can become active. Old released clients keep searching their old digest.

When a component is removed or renamed

A new digest omits it. Existing digests remain readable for a defined support window. Renames use a deprecated alias and replacementId; a name is never silently reassigned to unrelated code.

When a user has a custom registry

V1 searches it locally only. Proprietary metadata is never uploaded to HeyGen implicitly. A future hosted-custom-index feature requires a separate consent, tenancy and deletion design.

04 · real users

How people use it

CLI
hyperframes catalog hyperframes catalog search "animated pricing comparison" hyperframes catalog search "animated pricing comparison" --smart hyperframes catalog search "animated pricing comparison" --smart --json hyperframes add data-chart

Local is the default. --smart is explicit because it sends the query to HeyGen. A selected result flows through the existing runAdd installer and compatibility gate.

Studio

Search locally first

The block browser uses the same core scorer. A visible “Smart search · free with HeyGen” toggle signs in or reuses existing credentials. The UI labels fallback as “local results” rather than pretending a degraded query was smart.

SDK

searchCatalogLocal(artifact, query, filters) is pure and public. Remote HTTP remains an opt-in client adapter so rendering and core packages never gain a network dependency.

media-use extension
media-use resolve --type hyperframes \ --intent "a chart that counts up" --project . # force privacy/offline ... --local-only # explicitly use signed-in HeyGen smart search ... --provider heygen

media-use discovers; Hyperframes installs. It must not store component source under .media/ or invent a second catalog ledger. Its record points to the canonical catalog ID, digest and files written by hyperframes add.

Free means bounded

No credit charge

Authenticated catalog browse/search consumes zero HeyGen credits. OAuth is the recommended free sign-in path; API keys may authenticate developer automation without changing the zero-credit rule.

Still protected

Per-account, per-IP and global limits, bounded query length and top_k, timeouts and a circuit breaker remain mandatory. Free does not mean anonymous or unlimited.

05 · architecture

One result contract, two retrieval paths

Local path · GA candidate

query→bundled digest→exact + token ranking→typed results→runAdd
  • No auth, provider or network.
  • O(entries × query terms); measured before GA.
  • Custom registry supported locally.
  • Never auto-claims semantic understanding.

HeyGen path · gated beta

query + digest→auth→API→immutable index→compatibility gate→runAdd
  • Pinecone and embedding credentials stay server-side.
  • Dense and keyword arms may run concurrently, then RRF.
  • Any partial-arm failure is labeled; it is never called hybrid.
  • Unsupported digest falls back locally.

Ownership

Hyperframes OSS

Catalog truth, artifact schema, local scorer, CLI/Studio/SDK, installer.

↔

HeyGen API

Authentication, zero-credit policy, rate limits, index lookup, response envelope.

↔

media-use

Thin provider adapter and sign-in guidance. No duplicate catalog or installer.

Why Pinecone, and what we actually reuse

At 424 entries, Pinecone is not required for speed: a 424 × 1536 float32 matrix is only about 2.49 MiB. Pinecone earns its place by centralizing dynamic indexes, multilingual embeddings, quality tuning and future scale. Reuse Asset Scout’s environment-scoped namespace, lazy client, timeouts, metrics and failure discipline. Reuse Project Items’ closer text precedent for dense + BM25 arms and client-side RRF. Do not copy either model or scorer blindly: Asset Scout is multimodal dense-only, Project Items uses a different embedding model, and its RRF ranks are zero-based while the catalog evaluation is one-based.

07 · production boundaries

Code-complete is not production-ready

Local can fail open

Remote failure still leaves a deterministic search path over the exact installable digest.

Smart needs gates

Quality, capacity, privacy, abuse and catalog freshness must pass before a default changes.

No unbounded work

No unlimited query, top-k, candidate pool, pagination depth, retries, concurrency or index fan-out.

Capacity equations

embed calls / second = smart-search QPS × embedding-cache miss rate Pinecone reads / second = smart-search QPS × retrieval arms (1 semantic, 2 hybrid) monthly provider cost = requests × (embedding cost + index read cost) required tested capacity ≥ 3 × forecast peak QPS local work = catalog entries × normalized query terms

The plan deliberately does not invent a demand forecast. Product and API owners must record expected steady QPS, burst QPS, daily active searchers and queries per searcher before capacity approval.

Activation gates

GatePass condition before production traffic
QualityOn a product-specific top-5/10/20 corpus, smart is statistically no worse than local and improves at least one preregistered primary metric. Human usefulness and install success are measured separately.
ScaleLoad test at 3× recorded peak forecast with bounded queues; no error-budget breach, connection leak or unbounded memory growth.
LatencyAPI owner approves explicit p50/p95/p99 targets after a dev benchmark. CLI timeout is longer than the approved p99 but still short enough to fall back without blocking work.
AvailabilityDashboard and alerts cover auth, embedding, Pinecone, stale/missing digest, rate limit, fallback and install outcome. Kill switch forces local immediately.
FreshnessA release cannot activate until the exact digest is indexed, counted, sampled and query-smoked. Old namespaces remain until the supported client window expires.
PrivacyRaw query absent from analytics, structured logs and error payloads; cache keys use a digest; retention and access are documented.
AbuseAuth required, body/query size bounded, limit ≤ 50, cursor depth bounded, per-account/IP/global rate limits and provider circuit breaker tested.
08 · failure and edge matrix

How the system behaves when reality is messy

User is not signed inLocal works. --smart explains the free OAuth login path and makes no remote request until the user signs in.
OAuth token expiredRefresh once through the shared credential code. A second 401 becomes an auth error and local fallback; never retry forever.
HeyGen / Pinecone / embedder downOne bounded request, circuit breaker, explicit “showing local results” fallback. Do not cache the failure as an empty catalog.
One hybrid arm failsDo not label the surviving list “hybrid.” Return a typed degraded state or fail smart search so the client can choose a clearly labeled local result.
Client digest is unknownReturn catalog_version_unavailable with supported upgrade guidance. Never search “latest” and send entries the client cannot install.
Item removed during rolloutOld clients query their old namespace; new clients query the new digest. Retention policy, not mutable aliases, controls rollback.
Duplicate or renamed IDArtifact generation fails. Rename requires a deprecated alias and replacement; stable identity cannot be reused for different code.
Primitive has no install pathIt is excluded from public results. Searchability requires installability or a documented “reference-only” result type the client knows how to open.
Registry is unreachableBundled metadata still searches. Install reports that source files need network; browsing success must not be confused with offline install success.
Custom private registryLocal only in V1. No metadata leaves the machine. Smart indexing is a future separate product with explicit consent and tenant deletion.
Empty / huge / hostile queryEmpty means browse. Server and client reject over-limit UTF-8 bodies; output escapes metadata; query is data, never executable prompt or HTML.
Concurrent release and searchBuild a new immutable namespace first, smoke it, then advertise the digest. Never mutate the namespace currently serving requests.
429 or exhausted service budgetSearch remains zero-credit but rate-limited. Respect Retry-After, do not retry in the same command, fall back locally.
media-use calls itProvider shells the Hyperframes CLI with argv arrays, fixed timeout and source attribution. Hyperframes owns auth headers and installation.
09 · implementation plan

Eight units, with the risky decisions first

U0

Freeze the product contract

Goal: approve local-default / explicit-smart behavior, zero-credit policy, public result types, supported digest window and activation metrics.

Outputs: this plan, API RFC, threat/privacy review, demand forecast.

Verification: owners sign the boundary table; no code begins with unresolved identity/version semantics.

U1

Canonical search artifact

Hyperframes files: packages/core/src/registry/catalogSearch.ts, packages/core/schemas/catalog-search.json, scripts/generate-catalog-search.ts, registry/catalog-search.json.

Generate canonical JSON, digest, searchable text, aliases and installability proof. Package it via packages/cli/scripts/build-copy.mjs.

Tests: deterministic bytes, add/remove/rename, duplicate, missing file, non-installable primitive, schema drift, package contents.

U2

Pure local scorer

Files: packages/core/src/registry/searchCatalog.ts and tests.

Exact name/title/tag boosts plus deterministic normalized token overlap. No network, wall clock or mutable global cache. Stable tie-break by canonical ID.

Tests: empty, Unicode, punctuation, aliases, deprecated items, filters, stable ordering, 10× future catalog performance.

U3

CLI, Studio and SDK

Files: packages/cli/src/commands/catalog.ts, new catalog client modules, packages/cli/src/server/studioServer.ts, packages/studio/src/hooks/useBlockCatalog.ts, BlocksTab.tsx.

Add catalog search, --smart, --local-only, JSON contract and explicit fallback labels. Keep runAdd as the only installer.

Tests: CLI snapshots, no-auth, 401 refresh, 429/timeout/mismatch fallback, Studio route/browser flows, compatibility rejection.

U4

Immutable remote index

EF files: new heygen/core/common/clients/pinecone_hyperframes_catalog.py plus indexing activity/workflow.

Reuse Project Items document index pattern for keyword + dense fields and Asset Scout’s environment guardrails. Namespace by environment + catalog digest; IDs are canonical IDs.

Tests: idempotent upsert, deleted namespace retention, wrong-env refusal, partial batch, model/dimension mismatch, digest count and sampled payload parity.

U5

Authenticated HeyGen API

EF files: extend movio/api_service/app/controller/hyperframes_v3.py; add DTO/service and retrieval client tests.

GET …/catalog/items browses; POST …/catalog/search accepts free text. OAuth/API key, zero credits, heavy rate policy, source attribution, typed errors.

Tests: auth matrix, extra-field forbid, limits, cursor scope, query privacy, unknown digest, no raw score leak, degraded backend, OpenAPI.

U6

media-use adapter

Skill files: scripts/lib/registry.mjs, new hyperframes-provider.mjs, scripts/resolve.mjs, coverage/provider/privacy tests and references.

Add type hyperframes. Local invokes Hyperframes local search; --provider heygen explicitly invokes smart. Record canonical ID/digest/install output, never copy code into .media.

U7

Product-specific evaluation

Build preregistered top-5/10/20 tasks for real CLI/Studio users. Compare local, semantic and hybrid with the exact production fields, model and RRF convention. Measure recall, first-useful rank, successful install, latency and refusal separately.

Gate: no “smart” default or GA until the exact served strategy passes. The old 424-move prompt evaluation remains evidence, not authorization.

U8

Rollout and operations

States: off → internal shadow → employee opt-in → authenticated beta → limited ramp → GA. Every state has a one-switch local rollback.

Order: publish artifact/client → build/index digest → deploy API dark → shadow → verify dashboards/capacity → expose opt-in. Retain prior namespaces and strategy version for rollback.

Dependency order: U0 → U1 → U2 → U3. U4 and U5 may proceed only after U1 freezes identity. U6 depends on U3. U7 requires U2 + the actual U4/U5 candidate. U8 starts only when U7 and the scale/security gates pass.

Definition of done

  • Every returned item intersects the exact client digest and passes the existing compatibility gate.
  • Local search works without sign-in or network and is the visible fallback for every remote failure.
  • Smart search charges zero credits, requires authentication, observes approved limits and exposes its strategy/degraded state.
  • Adding/removing/renaming an item produces a deterministic new digest and cannot corrupt old clients.
  • CLI, Studio, SDK and media-use share identity, ranking result schema and installer ownership.
  • Quality, load, privacy, abuse, observability, rollout and rollback evidence are attached before GA.
10 · plain-language glossary

Terms used in this plan

Catalog
The list of Hyperframes things a user can discover and use: blocks, components and any primitives that have a real install/open contract.
Artifact
A generated JSON file shipped with a release. It is the search-ready view of the source manifests, not a second hand-edited catalog.
Canonical ID
A stable identity such as block:data-chart. Display names may change; the identity must not silently point to different code.
Digest
A SHA-256 fingerprint of canonical artifact bytes. Matching digests means client and server are talking about the exact same catalog.
Local / lexical
Ranking by exact names, tags and words on the user’s machine. It needs no embedding service and cannot have stale remote vectors.
Semantic
Ranking by meaning rather than shared spelling. “Make it feel faster” may find “speed ramp” even when those words differ.
Embedding / vector
A model turns text into a fixed-length list of numbers. Nearby lists are treated as similar meanings.
Pinecone
The hosted database that stores vectors and metadata and returns nearby entries. It is infrastructure, not the thing that makes an embedding intelligent.
BM25
A standard keyword-ranking method that rewards useful shared terms and discounts very common terms.
Hybrid / RRF
Hybrid combines word and meaning rankings. Reciprocal Rank Fusion (RRF) combines their positions instead of incompatible raw scores.
Top-k
The number of results returned or shown. “Top 20” means k=20.
Namespace
An isolated partition inside the vector database. Here it is pinned to environment and catalog digest so releases cannot mix.
OAuth
The browser sign-in flow that gives the CLI a revocable HeyGen access token without asking the user to paste an API key.
Rate limit
A bound on requests in a time window. The endpoint is free of credits, but still protected from accidental or abusive demand.
p95 / p99
The latency below which 95% / 99% of requests finish. They expose the slow tail that an average hides.
SLO
A measurable service objective for latency, availability or correctness that operators agree to meet.
Backpressure
Refusing or queuing bounded work when downstream capacity is full instead of creating unlimited concurrent calls.
Circuit breaker
A temporary stop on remote calls after repeated failures, giving the dependency time to recover while users get local results.
Shadow mode
Run smart search and measure it, but do not show its results. It reveals latency/failure behavior without changing the user experience.
Canary / ramp
Expose a new path to a small controlled group, then increase traffic only when its gates hold.
Rollback
Return to the prior client/index/strategy. Immutable digests make that a pointer/config change rather than a data reconstruction.
